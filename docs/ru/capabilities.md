# Настройка и диагностика

Настройте каждый `DbContext` с EF-провайдером Npgsql. Библиотека использует одно пространство имён — `EntityFrameworkCore.PostgreSQL.Extensions`. Здесь описаны регистрация, проверка требований к базе и типичные причины отказов.

<a id="registration-api"></a>
## Зарегистрируйте нужные операции

Для запросов с блокировкой строк:

```csharp
options.UseNpgsql(connectionString,
    npgsql => npgsql.UsePostgreSqlExtensions());
```

`UsePostgreSqlExtensions(this NpgsqlDbContextOptionsBuilder)` возвращает тот же builder. Регистрация без параметров и идемпотентна. Вызывайте её в callback настроек Npgsql для `AddDbContext`, `AddDbContextFactory` или регистрации пула контекстов, в зависимости от приложения. Настройки и состояние запросов изолированы между контекстами и пулами.

Интеграция блокировок сохраняет штатный транслятор Npgsql и заменяет фабрику генератора SQL. Конкурирующие замены генератора или транслятора до либо после регистрации не поддерживаются и приводят к явной ошибке. Ручная композиция через `UseInternalServiceProvider` не поддерживается. Дополняющие плагины, например Npgsql NodaTime, могут работать в обоих порядках регистрации; опорные версии указаны в [разделе о совместимости](compatibility.md).

Advisory-блокировки, вставка с пропуском конфликта, типизированное чтение времени, команда только для чтения и проверка возможностей не требуют регистрации блокировок строк. Для выражения с часами отдельно нужен `modelBuilder.MapClockTimestamp()` в `OnModelCreating`; см. [данные и транзакции](internal-mechanisms.md#clock-mapping-api).

<a id="target-api"></a>
## Целевая версия SQL и сервер

Фактическая целевая версия генерации SQL в Npgsql управляет трансляцией. Версия сервера, наблюдаемая через соединение, — отдельный факт. Цель можно выбирать штатными настройками Npgsql; опорные примеры используют `SetPostgresVersion(14, 0)` с PostgreSQL `16.14`.

Библиотека не меняет SQL target автоматически при подключении, не устанавливает расширения и не проверяет базу перед каждым запросом. Приложение определяет, какие базы, роли и резервные серверы нужно проверять и когда можно начинать работу.

<a id="probe-api"></a>
## Проверьте требования к базе

```csharp
var report = await PostgreSqlCapabilityProbe.CheckAsync(
    db, Array.Empty<PostgreSqlExtensionRequirement>(), ct);
Console.WriteLine(report.Outcome);
```

Пустой список требований проверяет соотношение провайдера, SQL target и сервера, а также возвращает перечень установленных расширений. Если приложению необходимо расширение, укажите его явно:

```csharp
var requirements = new[]
{
    new PostgreSqlExtensionRequirement("pg_trgm")
};
var report = await PostgreSqlCapabilityProbe.CheckAsync(db, requirements, ct);
```

`RequiredVersion` — необязательная строка точной версии, например `new PostgreSqlExtensionRequirement("pg_trgm", "1.6")`. Это требование вызывающего кода; пример не утверждает, что расширение установлено. Имена должны быть непустыми и уникальными; неверный список вызывает `ArgumentException`.

<a id="outcomes-api"></a>
### Как читать результат

| Результат | Значение |
|---|---|
| `Compatible` | Действующий SQL target не выше наблюдаемой версии сервера, и все переданные требования к расширениям выполнены |
| `Incompatible` | Неподдерживаемый провайдер/соединение, SQL target выше версии сервера или невыполненное требование к расширению |
| `Indeterminate` | Операция базы/провайдера завершилась исключением базы или invalid-operation до получения достоверных фактов |

Отчёт содержит `Outcome`, `SqlTargetVersion`, `ActualServerVersion`, `InstalledExtensions`, `UnmetRequirements` и необязательный `FailureType`. Для установленного расширения указаны `Name` и `Version`; для требования — `Name` и необязательный точный `RequiredVersion`. При сбое возвращается тип исключения без его сообщения. Отмена и остальные ошибки аргументов передаются вызывающему коду.

Проверка только для чтения обращается к `pg_catalog.pg_extension`. Учитываются установленные расширения; доступные, но не установленные не считаются установленными. Запись в перечне не доказывает, что текущая роль может вызвать любую функцию расширения или что соответствующий плагин Npgsql настроен. Успешный результат описывает одно соединение с базой в конкретный момент и не подтверждает все возможности запросов, другие роли/реплики или будущие резервные серверы.

При наличии используется корректно присоединённая текущая транзакция; открытие и закрытие соединения через EF уравновешены. Проверка не создаёт транзакцию или объекты базы. Вы определяете момент вызова, требования и влияние результата на готовность приложения. `Indeterminate` не подтверждает готовность.

<a id="troubleshooting-api"></a>
## Разбор типичных ошибок

| Симптом | Что проверить |
|---|---|
| Запрос с маркером не транслируется или сообщает об отсутствии регистрации | Добавьте `UsePostgreSqlExtensions()` в настройки именно этого контекста |
| Запрос отклонён до SELECT | Сопоставьте полное выражение и модель с [допустимыми формами](query-integration.md#query-shapes-api); проверьте глобальные фильтры и автоматическую загрузку навигаций |
| Блокировка/команда только для чтения сообщает об отсутствии текущей транзакции | Начните явную транзакцию EF и выполняйте команду на её контексте/соединении |
| Ошибка композиции сервисов | Уберите конкурирующие замены генератора/транслятора и ручную композицию внутреннего service provider |
| `55P03` при `NoWait` | Другая транзакция держит несовместимую блокировку; осознанно выберите реакцию приложения |
| Ожидание отменено или PostgreSQL прервал транзакцию | Обработайте штатную ошибку и завершите/замените транзакцию по правилам приложения |
| Insert-ignore отклоняет селектор или отображение | Выберите уникальный ключ без фильтра из модели и проверьте [ограничения отображений/defaults](internal-mechanisms.md#mapping-api) |
| Проверка вернула `Incompatible` | Посмотрите версии SQL target/сервера и `UnmetRequirements` |
| Проверка вернула `Indeterminate` | Посмотрите `FailureType`, доступность базы и состояние соединения/транзакции; скрывайте секреты в диагностике |
| `ClockTimestamp()` бросает исключение в клиентском коде | Используйте отображённую функцию в EF-запросе либо `ReadClockTimestampAsync` для прямого значения |

Не заменяйте отклонённый запрос с блокировкой запросом без неё. Штатные ошибки PostgreSQL могут находиться внутри обёрток EF/Npgsql; при необходимости изучайте внутреннее исключение и SQLSTATE. Библиотека не добавляет повторы или классификацию неопределённого результата commit.
