# Архитектура

Библиотека предоставляет переиспользуемые PostgreSQL-расширения через естественные для EF API. Публичное поведение определяют [блокировки](query-integration.md), [данные и транзакции](internal-mechanisms.md), [настройка и диагностика](capabilities.md). Здесь описаны внутренние границы для сопровождающих библиотеку.

<a id="package-design"></a>
## Пакет и механизмы интеграции

Один упаковываемый runtime-проект нацелен на `net10.0` и экспортирует пространство имён `EntityFrameworkCore.PostgreSQL.Extensions`. Внутренние каталоги разделяют ответственность; концептуальные слои не требуют отдельных сборок. В репозитории также есть один тестовый проект, пример изолированного потребителя пакета и сайт документации из Markdown. Лицензия библиотеки — Apache-2.0.

| Механизм | Ответственность | Точка интеграции |
|---|---|---|
| Интеграция запросов | Блокировка точного вхождения отображённой таблицы | Типизированный маркер, expression interceptor, структурный генератор SQL и проверка выполнения |
| Скалярные выражения | Выражения с часами PostgreSQL | Дополняющее отображение EF `DbFunction` |
| Команды в транзакции | Advisory-блокировки и команда только для чтения | Параметризованные/штатные команды `DatabaseFacade` в заимствованной транзакции |
| DML по метаданным | Вставка одной строки с пропуском выбранного конфликта | Финальные метаданные EF, экранированные идентификаторы, типизированные параметры и прямое выполнение |

Типизированное чтение времени и проверка возможностей используют узкие пути с учётом соединения и транзакции. Механизмы независимы; общий интерфейс операций или dispatcher им не нужен. Штатные средства EF/Npgsql предпочтительны, когда обеспечивают нужный смысл. Новые возможности расширяют соответствующий механизм; новая абстракция обосновывается реально общим поведением.

<a id="query-design"></a>
## Путь запроса с блокировкой

```text
typed IQueryable marker
  -> original expression and finalized-model validation
  -> immutable reserved intent tag
  -> native Npgsql translation
  -> final SELECT/table/column/selection-bound validation
  -> structural FOR ... OF quoted-generated-alias clause
  -> command-time fulfillment/service/transaction/bound validation
  -> PostgreSQL execution in the caller's transaction
```

Маркер строит вызов собственного определения метода. Без регистрации он остаётся нетранслируемым. Expression interceptor проверяет точную идентичность методов, перегрузки, свойства, корни модели и закрытый набор форм, затем передаёт намерение дальше. Штатный транслятор запросов остаётся установленным. Заменяется только `IQuerySqlGeneratorFactory`. Генератор независимо проверяет окончательную структуру и добавляет блокировку точного сгенерированного псевдонима корневой таблицы.

Command interceptor проверяет соответствие намерения и исполнения, фактические сервисы, присоединённые транзакцию/соединение и границы выбора при синхронном, асинхронном, кэшированном и скомпилированном выполнении. `CommandText` он не меняет. Одной пары внутренних тегов недостаточно для допустимой блокировки. Подделки и коллизии внутреннего протокола отклоняются, обычные постоянные теги сохраняются. Состояние неизменно и принадлежит конкретному запросу; корректность не зависит от изменяемого глобального состояния или `AsyncLocal`.

EF может извлечь литерал `Take(1)` в параметр до перехвата компиляции. Внутренняя идентичность границы должна сохраняться при трансляции, а значение при выполнении должно равняться единице. Проверка исходного выражения и финального SELECT с подходящим корнем нужны совместно, чтобы исключить расширение или перенаправление блокировки. Кэш, фабрики, пулы и композиция сервисов провайдера сохраняют это поведение.

Намерение полного набора UUID содержит столбец первичного ключа и необязательный Guid-префикс сортировки. Финальный SELECT сохраняет точный порядок корневых столбцов по возрастанию, один предикат принадлежности UUID и отсутствие ограничения количества. SQL принадлежности генерирует штатный Npgsql. Неизменяемые ключи под контролем приложения и фактическое наблюдение конкуренции обосновывают ограниченный протокол порядка; отсутствующие строки не защищены предикатной блокировкой.

Точка подключения генератора чувствительна к версии провайдера. Подавление EF1001 остаётся локальным для адаптера. Конкурирующие замены транслятора/генератора и ручная композиция внутреннего service provider приводят к явной ошибке. Дополняющие плагины продолжают работать; обычные запросы без маркера сохраняют штатный SQL и результат.

<a id="execution-design"></a>
## Выполнение и владение ресурсами

Операции требуют EF-провайдер и соединение Npgsql. Существующая транзакция используется, только если её `NpgsqlTransaction` присоединена к этому соединению. Блокировки строк, advisory-блокировки и команды только для чтения требуют явную транзакцию. Вставка с пропуском конфликта, чтение времени и проверка совместимости допускают самостоятельное выполнение в описанных границах.

Получение и освобождение соединения уравновешены через EF; ранее открытые соединения сохраняются. Приложение владеет begin/commit/rollback, политикой отмены, повторами и восстановлением. Ошибки PostgreSQL и провайдера передаются с исходными SQLSTATE и обёртками. Права приложения, lifecycle, правила ревизий, неопределённого commit и готовности хоста в библиотеку не входят.

Insert-ignore разрешает метаданные и типизированные значения до открытия соединения, использует штатную атомарную обработку конфликта и не меняет отслеживание. Mapping часов сохраняет изменяющуюся семантику вычисления. Текстовое advisory-хеширование выполняется сервером. Проверка возможностей независимо наблюдает SQL target и факты о сервере/установленных расширениях, не перенастраивая провайдер.

Чтение срока использует один материализованный серверный отсчёт и параметризованную арифметику интервалов с целыми миллисекундами. Литерал верхней границы сохраняет представимый диапазон .NET независимо от преобразования бесконечности провайдером. Отображения часов DateTime и DateTimeOffset используют одну volatile-функцию PostgreSQL; отдельные вхождения выражения сохраняют отдельные вычисления.

<a id="maintenance-design"></a>
## Границы сопровождения

Конечный набор публичных форм запросов и контракты отображений поддерживаются в руководствах. Новая форма, mapping или заявленная совместимость зависимости требуют явного документированного изменения поддержки и подходящих проверок провайдера/пакета. Сборка, сгенерированный SQL, unit-тесты, реальное поведение PostgreSQL и изолированное потребление устанавливают разные факты; сохраняйте штатные контрольные случаи и проверки отказов, соответствующие проверяемой гарантии.

Порядок работы описан в [Contributing](https://github.com/Keeyahto/EntityFrameworkCore.PostgreSQL.Extensions/blob/develop/CONTRIBUTING.md) и [правилах изменения кода](https://github.com/Keeyahto/EntityFrameworkCore.PostgreSQL.Extensions/blob/develop/.agents/code.md). Действующие руководства описывают контракты. Заменённые эксперименты и записи запусков остаются в истории Git. Сборка и публикация документации независимы от проверки runtime и пакета.

Общий ORM/UoW, универсальный SQL AST, скрытые менеджеры транзакций/повторов, исправление текста SQL для блокировок, автоматический выбор SQL target и управление жизненным циклом хоста в эту архитектуру не входят. Совместимость и правила выпуска описаны в [соответствующем разделе](compatibility.md).
